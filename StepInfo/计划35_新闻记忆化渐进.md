# 计划 35 —— 新闻记忆化渐进（当天新新闻 + 旧闻记忆摘要 + 落盘恢复）

> 依据：`StepInfo/00_需求与规则.md`（已重读）+ 用户 2026-08 指令（新闻记忆化渐进）。

## 用户需求（原始转述）

**目标**：
1. **新闻只当天见**：每天 AI 只能看到"这一天新发布的新闻"，不再从头看历史旧闻
2. **旧闻靠记忆留存**：每天新增新闻收进"近期新闻要点"记忆（滚动保留最近若干条），第二天以**摘要形式**呈现（非原文）
3. **记忆每日落盘**：新闻记忆 + "已投递到哪天"的进度跟随世界存档每天保存；重启后自动恢复，只投递新一天新闻，不重看不漏看

**改动**：
- 新闻台投递逻辑：记录"哪些新闻已看过"；模拟时只展示当天新增；后补旧新闻（没看过）算新的
- 跨天记忆增加新闻章节：当天新闻标题/要点并入记忆摘要（滚动保留最近若干条），第二天以"近期外界信息回顾"注入
- 每日落盘：state.json 增加 ①新闻要点清单 ②投递进度；每天结束写入、启动时读回
- 参数可调：新闻记忆保留条数（默认 5 条）

**不改**：注入时机（早晚各一）、上帝注入方式（剧本/命令行/控制台）、提示词占位符结构（memory_context / world_news）

## 设计

```
NewsBoard（投递逻辑）：
- delivered_ids: 已投递新闻集合（id = date_time_title）
- get_new_for(date) → 未投递且 date <= 当天的新闻（后补旧闻算新）→ 渲染 → 标记投递
- to_state()/restore_state()：delivered_ids 序列化（state.json: news_delivery）

HouseholdMemory（新闻记忆）：
- news_memory: [(date, title), ...] 滚动保留 config.NEWS_MEMORY_KEEP(默认5) 条
- add_news(items)：当天投递新闻并入（去重）
- get_prompt_context()：增加"近期外界信息回顾"章节（标题列表摘要）

World（落盘）：
- simulate_day：news 用 get_new_for（当天新增）渲染 {world_news}；投递列表 → day_result → memory.add_news
- save_state：增加 news_delivery（NewsBoard 状态）+ news_memory（按户）
- 启动：restore delivered_ids + news_memory → 只投递新一天
```

## 验证
1. 单测全绿（投递逻辑/记忆滚动/落盘恢复）
2. 495 剧本 3 天（每天 1-2 条新新闻）：第 2 天 step1 prompt 的 {world_news} 只含当天新增、昨日新闻出现在"近期外界信息回顾"（memory_context 内）摘要
3. 中途重启：state.json 读回后第 2 天不重放第 1 天新闻
4. git 提交

## 学术依据
- 用户"新闻只当天见"= 真实的新闻消费习惯（信息一次性感知）；"旧闻靠记忆"= Park et al. (2023) 记忆流的提炼（原文→摘要）
- 缓解长模拟的上下文膨胀：每天只注入新增信息，历史以压缩摘要保留（对应 SALM/Koley 2025 的 token 效率思想）
