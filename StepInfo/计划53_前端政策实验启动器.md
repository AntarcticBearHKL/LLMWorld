# 计划53:前端政策实验启动器(后台模拟一键启动)

## 做什么

前端新增"政策实验"区:政策下拉(6 种政策+组合)、天数/日期输入、
"启动后台模拟"按钮 → server `POST /api/worlds/<id>/simulate`
构造 population_runner 参数并交给 background_runner 系统级后台启动
(§一.9/14 工作流),任务面板自动监控。
受 §一.16 约束:启动前 confirm 对话框明确"将消耗 API tokens"，
用户点击=明确指示，合规。

## 为什么(依据)

1. **CoRenew (2026), arXiv:2607.25447**(第一轮已见):
   LLM-ABM 平台内置 "visualization and result export" +
   "evaluate the effects of alternative policy combinations"——
   政策评估 UI 是 LLM 模拟平台的标准能力。
   → 思考:本项目 policy 实验全靠命令行
   (--policy/--policy-schedule/--event),前端只能看结果;
   补上"启动"侧即闭环:选择政策→后台跑→任务面板→一键分析。
2. **运维经验**:用户手工模拟模式下命令行参数繁琐
   (policy 名/天数/日期/组合逗号),下拉+输入消除出错。

## 怎么做

1. `server.py`:
   - `POST /api/worlds/<id>/simulate`:
     body={policy, days, date, scenario}
     构造 sim_args=[world_id, --days N, (--date), (--policy/--scenario)]
     → background_runner.cmd_start(Namespace(sim_args=...))
     → 返回 {"job_id": ...}
   - 校验:policy 名先 Policy.from_name 试解析(报错返回 400)
2. 前端:新增"政策实验启动"面板——政策下拉(tou/subsidy/nudge/
   nudge_loss/peak_demand/ev_delay/tou,nudge/...)、天数输入(默认1)、
   日期输入(可空=自动续跑)、启动按钮(confirm 对话框)
3. 测试:TestPolicyExperiment——server 侧参数构造函数
   (纯函数化,可单测)
4. 任务面板已存在,无需改

## 怎么验证

- `python Implement/test_offline.py` 全绿
- server restart + 构造参数函数冒烟(不真启动模拟,仅验证参数拼接)
