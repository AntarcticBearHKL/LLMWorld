# 执行 3 —— 跨天记忆与习惯形成

> 对应 `计划3_跨天记忆.md`。

## 实际做了什么

### 1. 新建 `Implement/engine/memory.py`（家庭记忆模块）
- `HouseholdMemory`：每天结束后从当天结果生成本地结构化摘要（**0 额外 LLM 调用**）
- 摘要内容：每成员昨日活动概要（最多 8 段）+ 作息（起床/入睡）+ 家庭用电要点（总 kWh/基载/决策/高峰时段与瓦数/前 3 耗电电器）
- `get_prompt_context()` 输出"昨日记忆"章节文本，无记忆时返回空串

### 2. 管线接入
- `world.py`：`World.memory` 持有记忆；`simulate_day` 开始前注入 `memory_context` 给 Planner；每天结束后 `memory.update_from_day(day_result)` 更新记忆
- `planner.py`：`Planner` 接收 `memory_context`，渲染第一层 prompt 时传入
- `prompts/simulate_step1_macro_plan.md`：新增 `{memory_context}` 占位符（空时正常渲染，向后兼容）

### 3. JSON 自修复（计划外补充，实测发现）
- 第 2 轮冒烟中，第 2 天 Alice 第三层返回畸形 JSON（`Expecting ',' delimiter`）→ 原逻辑只能降级
- 新增 `utils.parse_json_with_retry()`：解析失败时用同一 prompt 重试一次（追加"只输出合法 JSON"指令），再失败才抛异常
- planner 三处 + executor 一处全部切换

### 4. 测试
- `test_offline.py` 新增 4 项 memory 测试（空记忆/作息提取/上下文内容/模板空渲染）→ **18 项全绿**
- `smoke_test.py` 增加第 2 天记忆注入检查

## 验证结果（world 495，2 天真实 API）

- 冒烟通过（exit=0），2 天五阶段全通，**无任何解析失败**（JSON 自修复生效）
- `[记忆] 昨日记忆已注入第 2 天计划` ✓
- 第 2 天 prompt 实际内容抽查：Alice/Bob 昨日活动清单 + 作息（起床 07:00、入睡 23:59）完整注入
- Token：2 天合计 151,849（prompt 39,554 + 输出 109,223；缓存命中 3,072）
- 日用电：Day1 11.75 kWh → Day2 14.69 kWh（正常波动）
- 发现：LLM 响应耗时方差大（同样 2 天，3.5 分钟 ~ 10+ 分钟），冒烟测试超时从 10 分钟放宽到 20 分钟

## 学术应用

- **Park et al. (2023) Generative Agents**：实现了"经验→记忆→影响下一日计划"的最简闭环（本地结构化摘要替代语义检索，为 LLM 反思/检索升级留接口）
- **Chetty et al. (2025)**：昨日用电高峰反馈进入今日计划 = 自反思习惯更新的简化版
