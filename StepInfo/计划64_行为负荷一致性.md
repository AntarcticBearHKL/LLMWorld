# 计划64:活动-负荷一致性检查(行为层保真度验证)

## 做什么

新增 `Implement/analyze_behavior_load.py`:把**活动时间线**
(02 层日志 coordinated_activities)与**户级负荷曲线**对齐,
检查"行为→负荷"管线的一致性:
- 每户:成员在家时段 vs 离家时段的平均负荷
  (预期:在家时段负荷更高——人在家才会用电)
- 负荷峰值小时与在家活动最密集小时的重叠度
- 每成员在家分钟数/活动数
输出报告 + 前端面板。这是 Xia et al. 2026 式"行为层验证"的
模拟世界落地(RQ1 行为→负荷管线的可解释性检查)。

## 为什么(论文依据 + 思考过程)

1. **Xia, Kuang & Hu (2026), arXiv:2607.17437**
   《Empirical Grounding Improves the Realism of LLM Agents
   Simulating Human Behavior During Disruptions》:
   LLM agent 模拟的保真度需要"行为层"验证(活动分布 vs 实证);
   其方法=把活动执行与人口行为统计对齐。
   → 思考:本项目 validate_baseline 只验证了负荷层(相关性 0.71),
   "行为→负荷"链路中间无人检查——LLM 可能"人在家但不用电"
   或"人不在家但负荷高"(电器被遗忘/误用),一致性检查
   是模拟质量的门禁。
2. **§一.6 验证要求**:每步必须有验证;本工具让用户手工模拟后
   可一键检查行为层合理性(运维经验佐证)。

## 怎么做

1. `Implement/analyze_behavior_load.py`:
   - 扫描 outputs/<world>/<postcode>/<house_id>/<scenario>/<date>/
     的 02_第二层_渐进协调_*.json(每成员活动)
   - 房间名集合:读 worlds/<id>/3168/<house_id>/household.json 的
     home.rooms(或从 03 层日志不依赖——用 household.json)
   - location ∈ 房间名 → 在家;否则离家
   - 与 1440min 曲线对齐:at_home_mean_watts / away_mean_watts /
     at_home_minutes / 峰值小时 vs 在家活动最密集小时
   - 输出 outputs/<world>/analysis/behavior_load_<scenario>_<date>.json
     (per_house 指标 + 汇总:一致性异常户列表
     [在家负荷≤离家负荷 或 峰值与活动错位])
2. `server.py`:`GET /api/worlds/<id>/behavior-load/<scenario>/<date>`
3. 前端:新增"行为-负荷一致性"面板
4. 测试:TestBehaviorLoad——合成 02 日志+曲线,
   断言在家均值>离家均值、峰值小时重叠、异常检测
