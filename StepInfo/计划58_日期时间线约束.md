# 计划58:世界日期时间线约束(禁止覆盖/回退/跳日)

## 做什么

对模拟入口( simulate.py / population_runner.py / server 模拟端点)
增加**世界时间线校验**:
1. **世界未开始**(worlds/<id>/state.json 无 date)→ 可随意设定开始日期
2. **已开始**(有 date)→ 只能**顺延继续**:
   - 不指定 --date = 自动从上一次日期+1 天继续(现有行为,允许)
   - 指定 --date 必须**恰好等于 上次日期+1**(防止跳过产生日期空洞);
     等于/早于上次日期 → 报错拒绝(禁止覆盖/回退/换时间)
3. **想重新开始同一时间线** → 提示用户使用**新的世界 ID**

## 为什么(依据 + 思考过程)

1. **用户 2026-08 明确指令**(§一.21 最高优先级来源):
   "模拟如果没有开始可以随意设定日期;如果开始了就只能够继续进行模拟,
   不允许覆盖或者换时间进行模拟;如果想要同一时间的话应该同一个世界
   开一个新的模拟"。
   → 思考:现状 World.__init__ 显式 start_date 直接使用,可任意回退/
   跳日,破坏 §一.12 世界日期连续(记忆/新闻投递按天推进,
   回退会污染记忆与 news_delivered 状态)。校验放**入口层**
   (runner/simulate 启动前统一检查),World 层保持被动。
2. **§一.12 世界日期连续**:state.json 断点续跑依赖日期单调,
   本约束是其保护机制(运维经验佐证)。

## 怎么做

1. `engine/world.py` 新增公共函数:
   - `get_world_last_date(world_id)` → state.json 的 date
     (None=未开始;格式 "2026年4月21日")
   - `validate_start_date(world_id, date_str)`:
     - date_str None → 返回续跑日期(上次+1)或 None(未开始,用默认)
     - 未开始 → 返回 date_str(任意)
     - 已开始:
       - date_str == 上次+1 → 返回
       - 否则抛 ValueError("世界已模拟至 X,只能继续(日期须为空自动续跑
         或等于 X 的下一天);想重新开始请用新的世界 ID")
   - 日期解析统一(兼容 2026-04-21 / 2026年4月21日 / 20260421)
2. `population_runner.main` 与 `simulate.py` 启动前调用
   validate_start_date 替换原 date 处理(保持"缺省自动续跑"语义)
3. `server.py` build_sim_args 的校验同样走 validate_start_date
   (simulate 端点 400 返回明确错误)
4. 前端启动器:若世界已开始,日期输入框 placeholder
   提示"留空=自动续跑(已开始世界不可换日期)"
5. 测试:TestTimelineGuard——未开始任意日期/已开始精确+1/
   已开始回退拒绝/已开始跳日拒绝/自动续跑

- 合成 state.json 冒烟校验逻辑
