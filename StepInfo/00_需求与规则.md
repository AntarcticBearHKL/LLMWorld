# StepInfo —— 开发需求与规则（每步规划/执行前必须重读）

> 本文件为**最高优先级约束**，任何一步的计划与执行都必须满足以下要求。

## 一、用户明确要求（原始转述）

1. **持续开发**：一直重复地开发下去，直到用户手工终止进程。永远不要停。
2. **代码可读性**：所有开发出来的代码，架构逻辑必须清晰，不懂代码的人也能一眼看懂。
   - 分层明确、命名直白（中文注释允许且鼓励）
   - 每个模块单一职责，模块间通过简单接口通信
3. **学术导向**：尽可能去任何论文网站（arXiv、Google Scholar、ACM、IEEE 等）搜索想法，并合理应用到本项目。
   - 应用时要在 StepInfo 执行记录中注明出处（论文名/作者/年份）与应用的原理
4. **API 约束**：
   - 只使用项目已有的 DeepSeek API 做测试（不新增其他厂商 key）
   - 允许多个 API 并行调用，但**同时并发不得超过 10 个**
5. **数据约束**：使用的数据尽可能围绕 **3168 / Clayton** 地区（墨尔本）展开。
   - 已有资产：clayton_3168_*.csv（人口普查数据）、vic_electricity_data.csv（维州真实电力）
6. **开发节奏**：走一步看结果 → 没问题再规划下一步 → 执行。
   - 每一步必须有"验证"环节（能跑就真的跑一遍，不能跑就说明原因）
   - 永远保留改进空间（每步结尾列出下一步候选方向）
7. **记录要求**：
   - 新建 `StepInfo/` 文件夹，按"计划1 / 执行1 / 计划2 / 执行2 …"顺序持续记录
   - 计划文件写"这步要做什么、为什么、怎么做、怎么验证"
   - 执行文件写"实际做了什么、结果如何、与计划的偏差、下一步候选"
8. **改动边界**：**只允许在 LLMWorld 文件夹内创建/修改文件**，其他文件夹（FIT5216、GenAgent 等）一律不动。
9. **git 同步**：每一步执行完必须 git 提交同步（LLMWorld 仓库）。

## 二、项目背景速查

- 目标：LLM 多智能体模拟 Clayton 3168 家庭用电行为 → 分钟级负荷 → 政策/事件干预实验
- 五阶段管线：宏观计划 → 渐进协调 → 丰富描述 → 用电决策 → 能耗计算
- 关键文件：
  - `Implement/engine/`：world / planner / executor / energy_calculator / generator / subagent / prompt / timeline / home / member / room / environment / weather_api
  - `Implement/generate.py`：世界生成（地区→分布→家庭）
  - `Implement/simulate.py`：单家庭逐日模拟入口
  - `Design/`：.aas 架构设计文档（与 Implement 保持同步）
  - `prompts/`：LLM 提示词模板（3 生成 + 4 模拟）
  - `worlds/<id>/3168/`：生成的世界数据
  - `Data/`：csv 数据资产（census / 电力）

1. **数据组织**：根目录的数据文件（clayton_3168_*.csv、vic_electricity_data.csv、clayton_translation_cache.json 及数据相关脚本）统一放入 `Data/` 目录，代码引用同步更新。
2. **模拟世界可视化（前后端分离）**：

   - 前端展示内容至少包括：世界/家庭列表、每日用电摘要、分钟负荷曲线、政策场景、新闻事件、跨天记忆状态
3. **前端持续同步**：**从本规则建立之日起，每一步开发的新功能都必须同步更新到前端展示**（新增数据源/场景/指标时同步加前端面板）。
