## 一、用户原始要求（全部指令，按时间序）

1. **持续开发**：一直重复开发直到用户手工终止。永远不要停。
2. **代码可读性**：架构逻辑清晰，不懂代码的人也能一眼看懂——分层明确、命名直白、单一职责。**注：与 §一.18 零注释标准配合：可读性靠命名与结构，不靠注释。**
3. **学术导向**：尽可能去任何论文网站（arXiv/Google Scholar/ACM/IEEE）搜索想法并合理应用；执行记录注明出处（论文名/作者/年）。
4. **API 约束（多次更新后现状）**：
   - 只用 DeepSeek API（.env 的 DEEPSEEK_APIKEY）
   - **并发不设任何上限**（用户 2026-08 解除限制；户级并行=世界家庭数）
   - **世界级约束**：每世界最多 10 户（population.py 校验）
   - **思考强度最低**：`config.REASONING_EFFORT = "low"`（官方枚举仅 low/high/max，见 api-docs.deepseek.com/guides/thinking_mode；传 medium 会被忽略=实际 high）；思考模式下不发送 temperature
   - **请求超时 600s**（运维发现：DeepSeek 对超限速请求服务端排队，5 并发中 2 个排队 4 分钟；120s 会误杀排队请求触发重试雪崩）
   - 重试 3 次指数退避；并发峰值仅观测
5. **数据约束**：数据围绕 **3168 / Clayton**（墨尔本）；数据文件统一 `Data/` 目录。
6. **开发节奏**：走一步看结果→没问题再下一步→执行。每步必须有验证（能离线就跑离线，不能说明原因）。永远保留改进空间。
7. **记录要求**：`StepInfo/计划N_*.md` + `执行N_*.md` 持续记录（计划写"做什么/为什么/怎么做/怎么验证"，执行写"实际做了什么/结果/偏差/下一步候选"）。
8. **改动边界**：**只允许在 LLMWorld/ 内创建/修改文件**；每步执行完 git 提交。
9. **后台工作流**：模拟放系统级后台（background_runner start，Popen 秒级返回）；进度用 status/读日志轮询；完成/报错后处理结果。禁止用 subagent 阻塞监听（Task 是阻塞式）。
10. **前端同步**：`frontend/index.html` + `server.py`（前后端分离、常驻 HTTP + CLI 查询）——**每一步新功能必须同步更新到前端展示**；界面实用清晰即可。
11. **环境信息接口**：`engine/environment_interface.py` 三模式（`config.ENV_MODE`）：real（真实 API，失败回退 config）/ config（墨尔本气候表按季节随机，种子可复现）/ manual（env_manual.json 固定值或范围）。
12. **世界日期连续**：一个世界是连续时间延续。state.json（worlds/<id>/state.json）每天保存 {date, memory_days 按户, news_memory 按户, news_delivery}；启动未指定 --date → 自动从上一次日期+1 天继续并恢复记忆/新闻进度。
13. **生成去作弊化**：世界/家庭/人物生成时**不得出现任何与用电行为强相关的词条**（EV 预设、energy_awareness、省电表述）——用电行为必须由 LLM 在模拟中自发涌现。测试 `test_no_energy_awareness_in_generation` 保障。
14. **服务器常驻**：开发期间系统级常驻服务器（`background_runner server start`）；**每次前后端修改后立即重启**（server restart）。
15. **禁止等待进程（硬性）**：任何情况下不允许 Start-Sleep 或等效阻塞等待；所有等待转系统级后台进程；即使"必须等结果"也要先做离线可做的工作；禁止宽泛进程匹配清理（教训：误杀过后台模拟）。
16. **模拟触发规则（硬性）**：**不随便添加功能后立刻开模拟**——开发模式=计划→执行→修正（离线测试）；**只有用户明确说"需要模拟/测试效果"才启动 LLM 模拟**。
17. **人口生成叠加 LLM**：程序化骨架（census 校准/成员关联/Big Five/电器）+ LLM 差异化细节（名字/职业/习惯/爱好/性格文本/家庭故事）；LLM 输出校验回退；防重复社区上下文。实现：population_llm.py。
18. **代码零注释（标准）**：**所有输出代码不允许任何注释**（# 注释、docstring、行内注释一律不要）；已有注释已全量清理；文档性内容放 StepInfo/ 与 Design/。
19. **手工模拟模式（现状）**：所有模拟数据与世界已删除，**由用户手工进行模拟**（工具链保留）。
20. **持续开发模式（2026-08 用户指令，最高优先级流程）**：**每一步都先去网上搜索相关论文**（arXiv/Google Scholar/ACM/IEEE），读论文→思考可能的开发方向→把论文功能/想法融合进本项目→实现。**永远不停**：做完一个功能觉得"做完了"就继续上网找新论文/新资料补充当前项目功能。每轮迭代循环：搜索论文 → 写 `计划N_*.md`（注明论文出处）→ 实现（零注释）→ 离线测试 → 前端同步 → `执行N_*.md`（注明论文出处）→ git 提交 → 继续下一轮。此模式与 §一.16（不主动开模拟）共存：论文驱动的功能开发不停，LLM 模拟仍仅在用户明确指示时运行。
21. **更新必须有来源（2026-08 用户指令，硬性）**：**任何功能更新/代码更新都必须有思路来源**（论文/文献/资料/运维经验），**禁止凭空捏造功能**。每轮更新必须体现思考过程：搜了什么 → 读了什么（论文名/作者/年/链接）→ 从论文想到什么 → 为什么融合进本项目 → 怎么实现 → 验证。思考过程写入 `计划N_*.md`（做什么/为什么/怎么做/怎么验证 + 来源分析）与 `执行N_*.md`（实际做了什么/结果/偏差/下一步候选 + 来源回顾）。无来源的功能更新视为违规。
22. **允许自由安装 Python 库（2026-08 用户指令）**：开发中可用 pip 随意安装第三方库（如 scikit-learn），无需事先询问；**成熟算法（聚类/降维/统计等）必须使用成熟库实现，禁止手写算法**（例：k-means 用 sklearn.cluster.KMeans）。新增依赖记录到 Design/ 或 README，测试仍以 test_offline.py 为准。
23. **arXiv 论文本地存档（2026-08 用户指令，硬性）**：**所有引用过的 arXiv 论文必须下载 PDF 到 `RefPaper/` 目录**（含历史引用未下载的，发现即补下载）；文件名=论文标题（统一整理格式：Windows 非法字符 `\ / : * ? " < > |` 替换为空格，连续空格压缩，`:` 规范为 ` - `）；`RefPaper/README.md` 维护索引（标题/作者/年/arXiv ID/引用位置），引用新论文时同步更新索引并下载。非 arXiv 论文（期刊等）只记录索引不下载。
24. **API 余额不足终止规则（2026-08 用户指令，硬性）**：**运行/开发过程中若 API（DeepSeek）返回余额不足类错误**（insufficient balance / 402 / 余额不足等），**立即终止本次任务并结束对话**，不做任何后续尝试（不重试、不降级、不继续开发）。剩余工作写入 `StepInfo/执行N_*.md`（已做到哪一步/待办），便于下次对话接续。

## 六、关键设计决策与运维思考（重要背景）

1. **DeepSeek 超限速排队**：并发 20+ 时服务端对超限速请求排队（实测 5 并发中 2 个排队 4 分钟），timeout=120 会误杀排队请求触发重试雪崩 → timeout 600s；requests 的 read timeout 对排队连接不触发
2. **requests 挂起排查**：曾误判为代码死锁，实为服务端排队（压力测试复现 20 并发 10 分钟无响应）；进程级后台 + status 轮询是唯一正确等待方式
3. **零注释清理的坑**：`src.rfind("\n", 0, col)` 把列号当文件偏移（行前缀判定全错）→ 按行号直接取前缀；docstring 删除导致空块 → 补 pass；BOM 由早期 PowerShell Set-Content 写入（utf-8-sig 处理）
4. **多户并行 state 覆盖**：save_state 按户存储（dict{house_id}）+ 原子写（tmp+rename）
5. **同日公平对比**：连续时间线下政策对比必须同日基线（跨日基线会被天气/波动误导——pop04 案例：跨日显示"TOU 无效"，同日显示 -8.98%）
6. **宽泛进程匹配教训**：`Get-Process python | Stop-Process` 误杀后台模拟 → 清理必须精确 PID
7. **Windows 编码**：后台子进程用 `-X utf8`（GBK 默认会乱码导致进度解析失败）；PowerShell 发送中文 JSON body 会丢失字符（浏览器 fetch 无此问题）
