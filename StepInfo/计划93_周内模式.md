# 计划93:周内模式分析(工作日 vs 周末)

## 做什么

新增 `Implement/analyze_weekday.py`:扫描多日模拟数据,
按**工作日/周末**分组对比负荷指标(日均kWh/峰值/晚峰/峰时),
输出 + 前端面板。验证 Jin 2021 主张
(星期是负荷变异第二驱动,仅次于温度)。

## 为什么(论文依据 + 思考过程)

1. **Jin et al. (2021), arXiv:2102.11027**(RefPaper 已存):
   负荷形状变异驱动排序:温度 > 季节/星期
   → 计划85/87 已覆盖季节与温度,本步补"星期"维度。
2. **作息锚定(计划68)**:step1 prompt 已有工作日/周末
   作息锚点差异 → 分析侧验证 LLM 是否真的产生了
   工作日-周末行为差异(引擎改进的闭环验证,运维经验)。

## 怎么做

1. `Implement/analyze_weekday.py`:
   - 复用 analyze_variability.scan_house_daily_profiles
   - 日期→星期(工作日/周末)
   - 分组:样本数/日均kWh/平均峰值/晚峰kWh/平均峰时
   - 输出 weekday_<scenario>.json
2. `server.py`:`GET /api/worlds/<id>/weekday/<scenario>`
3. 前端:新增"周内模式"面板
4. 测试:TestWeekday——工作日/周末分组、周末晚峰更晚、
   空数据报错

## 怎么验证

- `python Implement/test_offline.py` 全绿
- 合成数据 CLI 冒烟
