# 计划59:前端开启模拟体验完善(任务跟踪 + 停止 + 结果自动刷新)

## 做什么

完善前端"开启模拟"闭环(用户 2026-08 指令:
"前端应该添加开启模拟的选项,模拟会自动使用操作系统级别的
后台任务执行,然后前端可以刷新出来结果"):
1. 启动模拟后**自动轮询任务状态**直到完成/报错,
   完成后自动 refresh() 刷新全部结果面板并提示
2. 任务面板增加"停止"按钮(running 任务可终止,
   background_runner stop 精确 PID,§一.15 禁止宽泛清理)

## 为什么(依据)

1. **用户 2026-08 明确指令**(§一.21 最高优先级):
   "开启模拟的选项 + 系统级后台任务 + 前端刷新出结果"。
   → 思考:计划53已有关键部分(政策下拉/后台启动),
   缺"结果自动刷新"的闭环:现在启动后要等 10s 轮询碰运气,
   任务完成后没有显式提示;停止能力也缺失。
2. **§一.9 后台工作流 + §一.15 精确 PID**:停止必须走
   background_runner.stop(精确 PID 清理,禁止 Get-Process 宽匹配)。

## 怎么做

1. `server.py`:`POST /api/jobs/stop/<job_id>` →
   background_runner.cmd_stop(Namespace(job_id=...)) → {"ok"}
2. 前端:
   - `startSimulation()`:启动成功后进入任务跟踪循环
     (每 2s 查 /api/jobs,该 job 状态离开 running →
     刷新任务面板+refresh() 全部结果+提示"模拟完成/失败")
   - 任务面板 running 任务加"停止"按钮(confirm 后调
     /api/jobs/stop/<id>)
3. 测试:TestSimArgs 不变;stop 端点逻辑简单(调 cmd_stop),
   轻量验证 job 不存在时返回错误(不真启动)

## 怎么验证

- `python Implement/test_offline.py` 全绿
- server restart + API 冒烟(stop 不存在 job → 400)
