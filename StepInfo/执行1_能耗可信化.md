# 执行 1 —— 单家庭日模拟能耗结果可信化

> 对应 `计划1_能耗可信化.md`。执行时间：开发会话第 1 轮。

## 实际做了什么

### 1. 新建公共工具模块 `Implement/engine/utils.py`
- `format_json_compact` / `save_log` / `parse_time` / `parse_time_range` / `parse_json_response` / `validate_appliance_decisions`
- 从 planner.py / executor.py / timeline.py 抽取，消除三处复制粘贴

### 2. 重写 `Implement/engine/energy_calculator.py`（核心修复）
- **常开基载计入**：遍历 `home.appliance_registry` 中 always_on 电器，按 `daily_energy_kwh/24` 平摊进每一分钟。冰箱 1.2 kWh/天 → 50W 持续
- **家庭级 1440 分钟总负荷曲线**：新增 `house_load_profile_1440min.json`（单位 watts、峰值/峰值时间、逐小时均值）→ 论文 RQ1 核心产出
- **校验警告**：非法 unique_id/action 进入 `validation_warnings`，汇总写入 `总用电汇总.json`
- 每电器分钟曲线从布尔标记升级为瓦数数组（支持叠加）

### 3. 重写 `Implement/engine/subagent.py`
- `ThreadPoolExecutor(max_workers=10)` —— 满足用户硬性约束"并发 ≤ 10"
- 指数退避重试（3 次，2s→4s→8s），最终失败抛 `LLMCallError`（绝不返回错误字符串）
- 移除 GLM 调用路径中对主流程的依赖（DeepSeek 为唯一测试后端）

### 4. 重构 planner.py / executor.py / timeline.py
- 全部改为引用 utils（删除 `format_json_compact`、`_save_log`、本地时间解析的重复实现）
- executor：解析失败显式记录进 `validation_warnings`，不再静默

### 5. 修复 simulate.py 的"配置丢失"bug
- 旧代码 `add_appliance_by_name(type)` 丢弃 household.json 里的功率/日耗能/品牌，统一用默认值
- 改为 `create_appliance_from_config(type, config, location/owner)`，真实配置生效

### 6. 新建 `Implement/test_offline.py` —— 14 个离线测试全绿
- 时间解析（含跨天/多段修复）、时间线装载排序、能耗计算含基载、分钟曲线、校验警告、并发配置上限
