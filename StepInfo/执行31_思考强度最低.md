# 执行 31 —— 思考强度调至最低（DeepSeek 官方文档修正）

> 依据：`StepInfo/00_需求与规则.md` §一.4（已重读）+ 用户 2026-08 指令："把所有模拟使用的模型思考强度调整到最低，联网找到 deepseek 的文档参考官方 api 修改"。

## 官方文档调研（api-docs.deepseek.com）
- **思考模式参数（OpenAI 格式）**：`{"thinking": {"type": "enabled"}}` + `{"reasoning_effort": "low/high/max"}`
- **effort 映射表**：deepseek-v4-flash 传 low → 实际 low（最低）；传 high → high；默认 high
- **关键发现**：官方枚举**只有 low/high/max**——之前代码传的 `"medium"` 是非法值，会被忽略 → **实际一直是默认 high**（这正是 thinking 慢 90 倍的原因之一）
- 思考模式下 temperature/top_p/presence_penalty/frequency_penalty **不生效**（文档明确），请求中不应发送

## 修改
1. `config.REASONING_EFFORT = "low"`（flash 最低档；用户指令）
2. `subagent.call_deepseek`：thinking=True 时不再发送 temperature（非思考模式仍发送）；reasoning_effort 走 config
3. 测试：`test_reasoning_effort_lowest`（断言 low + 官方枚举）→ 64 项全绿

## 实测
- thinking=True + effort=low：**8.9 秒**（之前 high 约 3 分钟 → **~20 倍提速**），reasoning_content 正常返回（1248 字符）
- 注：THINKING 默认仍为 False（2 秒级）；low 档思考供需要思维链的场景使用

## 影响
- 未来所有模拟（job_006 起）使用 low 档思考（若开启）与非思考模式
- job_005（运行中）仍为旧代码（medium→实际 high）——运行不受影响，结果不受新配置污染
