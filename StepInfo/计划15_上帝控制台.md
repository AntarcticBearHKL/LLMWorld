# 计划 15 —— 上帝交互控制台 + 多日新闻连载验证（记忆×新闻协同）

> 依据：`StepInfo/00_需求与规则.md`（已重读）+ 用户"上帝模式"需求深化。

## 为什么做这步

1. **上帝控制台**：目前注入事件要手编 JSON 或用 --event 参数，体验不够"神"。做一个交互式 CLI：模拟逐日推进时，上帝（用户）随时可以输入新事件，实时进入当天/次日模拟。
2. **多日连载验证**：跨天记忆（计划3）× 新闻（计划13）从未协同验证过——连载新闻（战争升级→缓解）跨天演化如何改变行为轨迹？这是论文"动态行为演化"章节的基础实验。

## 做什么

| # | 任务 | 文件 | 验收 |
|---|---|---|---|
| 1 | 交互式上帝控制台：逐日模拟前询问是否注入新事件（写入内存新闻台，同日即生效） | 新建 `Implement/god_cli.py` | 命令行交互可用，事件实时生效 |
| 2 | 495 多日连载验证：2 天模拟（新闻剧本 04-21 战争→04-22 返利），检查记忆×新闻协同 | 运行（~20万 token） | 第 2 天计划含昨日记忆 + 今日新新闻 |
| 3 | 单测：god_cli 的事件注入函数（可离线测的部分） | `test_offline.py` | 全绿 |
| 4 | git 提交 | | |

## 控制台设计（保持可读）

```
python Implement/god_cli.py 495 --days 2 --date 2026年4月21日
第 1 天模拟前：
  [上帝] 要注入新事件吗？(输入 日期|标题|内容，回车跳过，q 退出)
  > 2026-04-21|暴风雨预警|气象局发布强降雨预警，可能停电
  已注入 → 当天模拟
  ...
第 2 天模拟前：同样询问
```

- 注入事件直接进 `world.news`（内存），当天 prompt 即生效（不需要等文件重读）
- events.json 剧本仍自动加载（两通道并存）

## 怎么验证
1. 单测（解析/注入逻辑）全绿
2. 495 跑 2 天：检查第 2 天 step1 prompt 同时含"昨日记忆"和"04-22 新闻"
3. 目视行为轨迹：第 2 天是否延续第 1 天的节能决策
4. git 提交
