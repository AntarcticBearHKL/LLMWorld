# 计划 3 —— 跨天记忆与习惯形成（行为引擎核心卖点）

> 依据：`StepInfo/00_需求与规则.md`（已重读）。对应论文 Park et al. (2023) 的记忆-反思-规划循环、Chetty et al. (2025) 的自反思习惯更新——当前系统"每天失忆"，是本项目与论文主张最大的实现缺口。

## 为什么做这步

现状：`World.simulate_day` 每天从零生成全新计划，昨天的行为对今天毫无影响。这导致：
1. 无法模拟"习惯"——论文综述明确指出"习惯是家庭用电的关键驱动因素"（Wang et al. 2021），无记忆就无习惯
2. 无法模拟对政策的长期响应（今天的决策影响明天的行为，如连续两天的高电价）
3. 论文 RQ2/RQ3 的干预实验失去时间维度

## 做什么（最小可用版本，不加新 LLM 调用）

| # | 任务 | 文件 | 验收 |
|---|---|---|---|
| 1 | 家庭记忆模块：从一天结果生成"昨日摘要"（本地结构化，0 额外 LLM 调用） | 新建 `Implement/engine/memory.py` | 摘要含：活动概要/用电要点/成员状态 |
| 2 | 记忆接入管线：`World` 持有 memory，`simulate_day` 把昨日摘要注入第一层 prompt | `world.py` + `planner.py` | 第二天 prompt 含 `yesterday_summary` 章节 |
| 3 | 第一层 prompt 模板增加可选"昨日记忆"章节 | `prompts/simulate_step1_macro_plan.md` | 模板渲染不破坏旧调用（缺省为空） |
| 4 | 离线单测：memory 摘要生成 + 模板渲染 | `test_offline.py` 扩展 | 全绿 |
| 5 | 集成验证：world 495 连跑 2 天，检查第 2 天计划含昨日延续特征 | 运行冒烟扩展 | 日志可见摘要注入 + 行为延续 |

## 设计（保持"不懂代码也能看懂"）

```
World
 └─ memory (HouseholdMemory)
      ├─ per_member_memory[姓名] = 昨日活动概要(时间段/位置/活动) + 用电要点(kWh, 高峰时段)
      └─ update_from_day(day_result)  # 每天结束后从时间线+用电信息生成
第一层 prompt 追加：
  ## 昨日记忆（帮助你保持习惯连续性）
  昨天你做了：...
  昨天家庭用电：...（高峰在18-21点，空调3小时）
```

记忆内容选择（信息增益最大、token 最少）：
- 活动概要：昨日主要活动序列（本地从 timeline 拼装，最多 8 段）
- 用电概要：昨日总 kWh、高峰时段、每成员贡献（从 总用电汇总.json 读）
- 状态：起床时间/入睡时间（从 timeline 首尾段推断）→ 支撑"作息习惯"表达

## 怎么验证

1. `test_offline.py` 全绿（新增 memory 测试）
2. 冒烟扩展：`python Implement/smoke_test.py 495 --days 2` → 检查第 2 天 01 阶段日志含"昨日记忆"章节且内容非空
3. 对比第 1/2 天的起床时间、活动结构是否出现延续（目视检查日志）
4. git 提交

## 学术依据（注明出处）

- **Park et al. (2023) Generative Agents**：记忆流 + 反思 + 计划循环。本步实现其中"经验 → 记忆 → 影响下一日计划"的最简闭环（本地结构化摘要代替语义检索，为后续扩展留接口）
- **Chetty et al. (2025)**：LLM 框架通过自反思更新习惯，捕捉季节/情境变化 → 本步的"昨日用电高峰反馈"即其简化版
- **Wang et al. (2021)** 实证结论："用电习惯是消费行为的关键驱动，价格影响有限" → 记忆机制直接服务该实证对齐目标
