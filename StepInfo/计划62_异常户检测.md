# 计划62:异常户检测(消费模式 z-score 综合评分)

## 做什么

新增 `Implement/analyze_anomalies.py`:基于**多维度消费特征**的
异常户检测——对世界内各家庭(某场景最新日)计算
日kWh/峰均比/负荷率/峰值叠加事件数,逐维 z-score,
|z|>2 标记异常,输出综合评分与原因分解,前端展示。
用于识别 LLM 模拟中"行为异常户"(如 EV 充电滥用重现、
基载异常、叠加失控),也是计划6 发现的 EV 107kWh 异常户的
系统性检测工具。

## 为什么(论文依据 + 思考过程)

搜索过程:arXiv search UI 搜 "anomaly detection smart meter
residential electricity"(0 结果)→ 改搜 "electricity theft
detection consumption pattern"(7 篇)→ 选定 3 篇:

1. **Banik et al. (2023), arXiv:2306.02473**《Anomaly Detection
   Techniques in Smart Grid Systems: A Review》(IEEE AIIOT):
   综述把异常检测按"消费模式统计特征/时序/图"分类,
   统计特征(z-score/聚类距离)是最基础且可解释的一类。
   → 思考:本项目无标签数据(无真实异常标注),监督学习不可用;
   统计 z-score 是可解释、离线可测的最优选择。
2. **Glauner et al. (2017), arXiv:1702.03767**:
   NTL 检测依赖"不规则消费模式"特征(量级/形状/峰特性)
   → 特征选择:日kWh(量级)/峰均比+负荷率(形状)/叠加事件(模式)。
3. **Olowookere et al. (2026), arXiv:2604.03344 (SGEIS)**:
   异常消费模式检测的实际价值(电能窃取/高耗能户识别)
   → 佐证本项目场景:模拟世界内高耗能/异常户自动筛查。

## 怎么做

1. `Implement/analyze_anomalies.py`:
   - 复用 load_profile_cluster.scan_house_profiles(最新日)
   - 每户特征:total_kwh / peak_to_mean / load_factor /
     peak_overlap_count(threshold=8000)
   - 户数 ≥3 时逐维 z-score;|z|>2 标记该维异常
   - 综合:异常维数 + max_abs_z;输出
     outputs/<world>/analysis/anomalies_<scenario>.json
     (per_house 特征+z+标记,anomalies 列表+原因)
2. `server.py`:`GET /api/worlds/<id>/anomalies/<scenario>`
3. 前端:新增"异常户检测"面板(表格:户/日kWh/峰均比/叠加/
   z-score 着色/异常原因)
4. 测试:TestAnomalies——构造 3 户(1 户 EV 式高耗能+
   叠加)→ 该户被标记异常,其余正常;户数不足跳过
