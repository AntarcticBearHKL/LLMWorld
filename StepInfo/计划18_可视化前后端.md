# 计划 18 —— 模拟世界可视化（前后端分离：浏览器前端 + 常驻后端）

> 依据：`StepInfo/00_需求与规则.md` 第五节（已重读）：前端浏览器交互、后端常驻服务+命令行交互、界面实用清晰、此后每步新功能同步前端。

## 为什么做这步

模拟结果目前只能看 outputs/ 里的 JSON，无法直观"看到世界在变动"。本步交付：
1. **常驻后端**（`Implement/server.py`）：Python 标准库 HTTP 服务，零新依赖；浏览器与命令行双通道
2. **浏览器前端**（`Implement/frontend/index.html`）：单页应用展示世界/家庭/日负荷/政策矩阵/新闻

## 架构

```
浏览器 ──HTTP──> server.py（常驻，localhost:8080）
                   ├─ GET /                → 前端页面（index.html）
                   ├─ GET /api/worlds      → 世界列表
                   ├─ GET /api/worlds/<id> → 世界详情（家庭数/类型/场景列表/日期列表）
                   ├─ GET /api/worlds/<id>/profile?scenario=&date=
                   │                        → 1440分钟曲线+摘要+逐户明细
                   ├─ GET /api/worlds/<id>/matrix → 政策/新闻场景对比矩阵
                   ├─ GET /api/worlds/<id>/events → 上帝剧本新闻
                   └─ GET /api/compare?world=    → 基线对齐指标
命令行（--query）：
    python server.py --query worlds
    python server.py --query days pop02
    python server.py --query profile pop02 --scenario tou
```

## 前端面板（实用清晰，不追求美观）

1. **世界选择**：下拉（worlds/ 目录）→ 显示家庭构成
2. **场景/日期选择**：policy/baseline/war_news/rumor_news + 日期
3. **负荷曲线**：canvas 手绘 24h 折线（1440 分钟降采样到 144 点），峰值/峰值时刻标注
4. **摘要卡片**：总用电/户均/峰值/晚峰时段用电
5. **逐户明细表**：每户 kWh + 峰值
6. **场景矩阵表**：baseline/tou/nudge/nudge_loss/subsidy/war_news/rumor_news 并排
7. **新闻面板**：events.json 剧本（上帝可见）

## 怎么验证
1. 起服务（后台线程方式测试）：requests 打各 API 返回 200 与正确 JSON
2. CLI --query 三连
3. git 提交

## 学术/工程依据
- 交互式可视化是 AgentSociety 等大规模模拟平台的标准组件（研究可复现性）
- 标准库 http.server：零依赖、可读性强，符合"不懂代码也能看懂"
